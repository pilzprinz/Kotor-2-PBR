# Changelog

## 0.4.1-dev (code review + refactoring session)

### Architecture & safety improvements

- **Configuration system (`pbr_config.{h,cpp}`).** New INI-driven config (`pbr_config.ini` next to the DLL) with safe defaults for all subsystems. Sections: `[general]` (enable/disable PBR, shadows, depth capture, file logger, GLSL pilot, tune overlay), `[logging]` (log level, file/diag toggles), `[performance]` (stats overlay, shadow cache limit, sibling cache limit), `[safety]` (SEH exception handler). `PbrConfig_Load()` called first in `DllMain`; all subsystem inits now check `g_config` flags. Deployed with a commented example `pbr_config.ini`.
- **SEH wrapper around `DllMain` init.** Init is now wrapped in `__try/__except` so a crash in one subsystem (missing GL extension, FBO failure) logs the exception code and continues with that subsystem disabled, instead of taking down the game process.
- **Resource cleanup on `DLL_PROCESS_DETACH`.** `PbrShutdown()` is now called alongside `ShutdownFileLogger()` on detach, clearing the texture id→name map and sibling cache.
- **`InitGL()` string safety.** Replaced manual pointer arithmetic (600-byte buffer, `while(*++c)` scan, hardcoded 14-char copy) with `GetSystemDirectoryA` + `snprintf` into a `MAX_PATH` buffer with bounds checking. Eliminates a potential buffer overflow if the system directory path is near 600 chars.
- **Sibling cache eviction.** `PbrGetSiblings` now enforces `g_config.siblingCacheLimit` (default 500). When exceeded, evicts the oldest half of the cache, freeing their GL textures via `glDeleteTextures`. Prevents unbounded memory growth during long play sessions with many area transitions.

### Bug fixes

- **`names[hash]` map pollution in `glFunctions.cpp`.** `my_glProgramString` used `operator[]` on the `names` map to look up a shader hash — `operator[]` inserts a default-constructed empty string for every unknown key, growing the map by one entry per unique shader upload (hundreds across a playthrough). Fixed to use `find()` + iterator check.
- **`GetFbo()` map pollution in `depth_capture.cpp`.** `GetFbo()` used `operator[]` on `g_fbos`, inserting phantom `FBOInfo` entries for every unknown FBO id referenced in attachment calls. Fixed to use `find()` and return a reset static default for unknown ids.

### Build system

- **Makefile updated** to include `pbr_config.cpp` in the source list.

## 0.4.0-dev (current — real shadow map subsystem)

### 2026-06-01 session (cont. — "Sun dir Z couples brightness+angle" diagnosed; normalize tried then REVERTED)

- **Why "Sun dir Z" changes brightness AND angle (diagnosis, no behaviour change kept).** The ARB FP (`fp_worldtex_diffuse_main.txt:171`, `:154`) feeds `tnD = env[27].xyz` **raw** into `N·L` and the sun-spec half-vector, so the sun dir's *vector length* is a hidden brightness multiplier: moving a dir slider both rotates the sun and rescales its length → brightness. The shadow map doesn't have this (`shadow_map.cpp:531` `V3Norm`s its copy), so shadow angle tracks but doesn't brighten — that asymmetry is the coupling the user saw.
- **Tried `normalize(tnD.xyz)` in the world FS → REVERTED.** Normalising decouples angle from brightness, but the GLSL material covers **only the static-world pair** (`vp_static_lit_fog + fp_worldtex_diffuse_main`, `glsl_program.cpp:516`); **characters are skinned → ARB `fp_model_*`, untouched**, still consuming the raw `env[27]`. Per-location `[601dan]` had `sun_dir=(0,0.2,0.2)` (len 0.283) used as a *dimmer* alongside `sun_diff_i=0.6`; normalising blew the world's sun terms up ~3.5× and saturated the shadow-contrast `nl`, while characters stayed weak → **world/character lighting mismatch** ("characters look dark against brightened ground"). Reverted both FS copies to raw `tnD.xyz`, restoring world↔character consistency and every saved per-location calibration. Decoupling would require normalising **all** lit shaders (world ARB + every `fp_model_*`) AND re-tuning all locations — deferred, not worth breaking dialed-in calibrations.
- **Shader review (GLSL pair).** Confirmed the FS/VS are already optimization-complete: the uniform-flag branch gating (skip up to 4 texture fetches + 2 POWs + 3 normalizes on flag-0 surfaces) is the dominant win and is in place. Remaining candidates (folding the two sequential scalar shadow multiplies, merging `ao`×`diffDim`) save ~2 ALU ops but reorder FP rounding — declined to preserve the documented IDENTICAL-output guarantee; texture fetches/POWs (already gated) dominate cost on the target RTX hardware. The ARB `.txt` set is the engine-faithful path and intentionally left untouched.

### 2026-06-01 session (cont. — ROOT CAUSE: GLSL override hijacked fixed-function draws [SOLVED] + HSV sun picker)

- **Skybox washed/overbright + grass mis-lit under GLSL = the override ran on FIXED-FUNCTION draws.** The breakthrough (after the per-draw census exposed `GL_FOG=0` on `dan_sky*` and `fpEn` on every surface): KOTOR draws the **skybox and grass with the ARB programs DISABLED** (fixed-function), but leaves the *previous* draw's program **binding id** in place. `GlslMaterial_Apply` matched the pair by that **stale `glGetIntegerv(GL_FRAGMENT_PROGRAM_BINDING_ARB)` id**, so the name check passed — then `glUseProgram` **overrides fixed-function too**, so the GLSL program rendered surfaces the engine never meant to shade (fog + sun → washed/overbright sky, camera-dependent grass). ARB mode left them fixed-function → clean, which is why the A/B diverged despite provably-identical shader math. **Fix:** gate the override on `glIsEnabled(GL_FRAGMENT_PROGRAM_ARB)` (the authoritative per-draw enable, not the stale binding id) — fixed-function draws fall back to the engine path, exactly as ARB mode renders them. One line; fixed sky + grass at once. Tradeoff: grass no longer receives the GLSL sun shadow (it's fixed-function now) — accepted. The long fog/secondary-color chase was all downstream of this: the sky never should have reached the fog code.
- **Sun color is now an HSV picker.** Replaced the 3 RGB sun-color sliders (`Sun color R/G/B`, env[28].yzw) with `Sun hue` (0–360°), `Sun saturation` (0–1), `Sun brightness` (0–2, = HSV value / the brightness slider). `PbrTune_PushEnvParams` converts H,S,V → R,G,B (new `HsvToRgb`) before pushing env[28].yzw, so the shader path is unchanged. Defaults = the old RGB (1.0,0.85,0.7) expressed as HSV (30°, 0.30, 1.0). INI keys `sun_color_*` → `sun_hue/sat/val` (per-location). Capture-from-view (F2) is direction-only, unaffected.
- **Removed the fog-debug viz from the FS** (it hijacked the `Shadow viz` slider to show the fog factor as grayscale) now that the sky is solved.

### 2026-06-01 session (cont. — full ARB-fidelity audit; fog moved per-pixel → per-vertex)

- **Line-by-line audit of the GLSL material vs the ARB source — port confirmed faithful.** Diffed `fp_worldtex_diffuse_main.{vs,fs}.glsl` against `vp_static_lit_fog.txt`, `fp_worldtex_diffuse_main.txt`, and `shadow_receive.inc`. Every term matches: VS 3-light `LIT` lighting (per-light `L=env_pos-wPos`, `DST` attenuation `c+l·d+q·d²`, ambient×env95 / diffuse×env94, scene-ambient env93, un-normalised world normal, env89.x init), world transform via VERTEX env[92/91/90], `result.color` alpha = env94.w; FS stock `d·(v+lm)`, normal+detail decode with the `nrm.w`-clobber AO quirk, Schlick `pow5` Fresnel + `F0=lerp(0.04,albedo,metal)`, energy `(1-F)(1-mt)` gated by usePbr, emissive `rough.a·emiScale·useEmi`, L0 & baked-sun Blinn-Phong (F-tinted, shadowed, fl.x-gated), sun diffuse (ungated, shadowed), sun-shadow global contrast, billboard term, AO global + diffuse-dim; and the shadow include (receiver normal-bias, K=env[100..102] projection, IGN dither, 4-tap diagonal PCF, the `tz≤1` far-plane gate, floor+strength). The flag-gated `if` branches (skip texture fetches / POWs when a flag is 0) are output-identical to the ARB's multiply-by-zero. **Uniform feed also verified faithful**: per-material env[20..23] (`pbr_state.cpp`) pushed per-draw in `UploadPerDraw`; global tune/sun env[24..30] (`pbr_tune.cpp`, set once per frame) cached per-frame in `UploadStable` — matches how the engine/mod actually sets each. Conclusion: the sky-fogged-to-fog-color symptom is **not** a shader or uniform divergence — it is draw-routing/geometry (which surfaces reach this pair, at what `|eye|`), pending the per-draw census.
- **Fog factor moved from per-pixel (FS) to per-vertex (VS), matching the ARB exactly.** The sole real divergence the audit found: the ARB VP computes the linear fog factor per-vertex into `result.color.secondary` (clamped, then interpolated); the GLSL FS was reconstructing it per-pixel from an interpolated `|eye|`. Now the VS computes `f = clamp(1-(|eye|·fb2+fb3),0,1)·gate` and passes it in `gl_TexCoord[5].w` (where `.xyz` is still world pos); the FS just `mix(d, uFogColor, .w)`. `uFogParams` moved VS-side (FS keeps only `uFogColor`); the C++ push is unchanged (same linked uniform location). This also matches the ARB's gentler per-vertex fog ramp on large distant ground tris instead of the perspective-correct per-pixel over-darkening. Shader-only (no rebuild).
- **Per-draw census added (diag).** `glsl_program.cpp` logs each DISTINCT TMU0 texture reaching the matched (vp_static_lit_fog + fp_worldtex_diffuse_main) pair with its per-draw depth-mask + fog color (`[glsl][census] tex=… dMask=… fog=…`), deduped + capped. Ground truth for whether the skybox/grass go through the GLSL material and in what state — to end the reasoning loop.

### 2026-06-01 session (cont. — fog gate must be PER-DRAW, not per-frame cached [root cause])

- **Skybox fogged solid = the fog gate was sampled once per frame, not per draw.** The debug viz (Shadow viz=1, FS outputs `vec4(fogAmt, fogDist/256, gate, 1)`) gave hard ground truth: the upper-screen geometry **does** go through the GLSL FS (debug-colored, not falling back to ARB) and sits at `fogDist ≥ 256` → `fogAmt = 1` → mixed fully to fog color → "skybox gone / flat wash". A line-by-line read of the ARB source (`vp_static_lit_fog.txt` 32-40, `fp_worldtex_diffuse_main.txt` 211-212) proved the fog **math** is identical (`f = (|eye|-start)/(end-start)`, `LRP d, f, fog.color, d`) — so the divergence had to be an *input*, not the formula. It was: the ARB VP evaluates `SLT t.x, 0.0, state.fog.color` **per draw** (the engine signals "no fog here" by zeroing `GL_FOG_COLOR` on the skybox/backdrop draw), but `glsl_program.cpp` read `glGetFloatv(GL_FOG_COLOR)` + computed the gate **once per frame** in `UploadStable` (guarded by `s_stableDoneFrame`), sampling whatever draw happened to be first — a fog-ON terrain draw → cached gate=1 applied to *every* draw incl. the sky. Every prior "fog experiment" unknowingly tested that stale per-frame cache, never the sky's real per-draw state — hence the deadlock. Fix: moved the `GL_FOG_COLOR` read + `gate = (color.r > 0)` into `UploadPerDraw` (one `glGetFloatv` per matching draw, alongside the existing per-draw env reads), exactly mirroring the ARB's per-draw `SLT 0, state.fog.color`. Sky draw → color zeroed → gate 0 → no fog → sky renders; fogged terrain keeps gate 1. `fogBehavior[2,3]` (the linear span) stay global. DLL rebuild + redeploy.

### 2026-06-01 session (cont. — fog gate corrected: color>0, not GL_FOG enable)

Correct distance-based partial fog (from the reliable `glGetFloatv` params) now mutes distant sky/foliage exactly as ARB does. The earlier flat-purple was purely `gl_Fog`'s mis-scaled factor → already fixed by sourcing start/end/color from `glGetFloatv`.

### 2026-06-01 session (cont. — skybox fix attempt 1: real GL fog state; wrapper gl_Fog is unreliable)

### 2026-06-01 session (cont. — Dantooine grass flicker + skybox vanish fixes [Z-gate: NOT the sky cause])

- **Skybox darkening/vanishing per camera angle = shadow receive had no Z-bounds gate (fixed, GLSL FS + ARB `.inc`).** The directional-shadow sample tested only the XY light-UV bounds (`outside [0,1]^2 -> lit`), never the light-space **Z**. The skybox sits beyond the light's far plane, so its light-NDC z clamps to `shZ=0.99`; the depth map only holds near scene geometry (much smaller depths), so the comparison reads the sky as **occluded by everything → shadowed** wherever it falls inside the (camera-anchored) XY bounds. As the box follows the camera, which sky faces are in-bounds flips → the sky darkens/reappears with view angle. Added a far-plane gate: fold `tz<=1` into the in-bounds factor so beyond-far receivers stay lit (`tz<-1`, in front of near, already reads lit via the existing `shZ`→0 clamp). GLSL FS: `inb *= step(tz, 1.0)` (free). ARB `shadow_receive.inc`: `SGE tmp.w,1.0,tmp.z; MUL tmp.x,tmp.x,tmp.w` (+2 instr, inserted while `tmp.z` still holds light-NDC z) — heaviest receiver goes ~200→~202, within ARBfp1.0 native limits on the 3070 (the existing 196–200-instr shaders already compile). Not added to `shadow_receive_self.inc` (models are never beyond the light far plane; keeps the near-ceiling `fp_model_*` shaders lower). Strictly an improvement over the faithful baseline: only un-darkens wrongly-shadowed beyond-far pixels; in-frustum receivers (`tz∈[-1,1]`) are untouched.
- **Dantooine grass darken/brighten per camera = `billboardshadow` volumetric darkening keyed to the unstable camera shadow map (fixed via sidecar).** `grass.txi` + `DANfx_grass.txi` each contained only `billboardshadow 1` → `ux.y=1` → the FS billboard/volume-shadow term `d.rgb *= 1-((1-shClip)*shadowDarken)` (the ONLY mod term touching grass — it has no normal/rough sibling, so Fresnel/spec are off). `shClip` is sampled from the camera-following shadow map (range 50, orbit 0.5), so grass flips dark/lit as it enters/exits the box → the reported flicker, and it's a fake volumetric darken rather than a real cast/received shadow. Set both sidecars to `billboardshadow 0`: grass now uses the normal world-receiver path (real directional shadow + contrast) like other geometry instead of the volumetric hack. Sidecar-only change (reversible, no rebuild; re-read on texture load).

### 2026-05-31 session (cont. — GLSL material perf pass, no quality change)

- **FS dead-work elimination via uniform branching (GLSL-exclusive; output-identical).** ARBfp1.0 has no branches, so `fp_worldtex_lm_fog_alpha` always sampled the normal/rough/metal siblings and ran the L0 + baked-sun spec POWs even on surfaces whose per-draw flags (`fl.x/y/z/w`, `ns.y`) zeroed them out — and the catch-all runs on a LOT of plain/sky/foliage geometry. The GLSL FS now guards: the rough sample on `fl.y>0||ns.y>0`, the metal sample on `fl.z>0`, the normal+detail samples (2 fetches) on `fl.x>0||fl.w>0`, and the F-tinted spec block (F0/F + 2 POWs + 3 normalizes) on `fl.x>0`. The flags are per-draw uniforms ⇒ branches are coherent (no warp divergence) and texture LOD stays valid. Output is provably identical: when a flag is 0 the guarded term was already multiplied to 0/no-op (verified incl. the AO quirk — when `fl.w==0`, `ao=1` regardless of the skipped `nrmInvLen`). Worst-case plain surface now skips up to 4 texture fetches + 2 POWs. Required saving raw `albedo` for F0 (computed pre-combine) and moving the shadow block ahead of a single merged spec block (additive specs commute, so the value feeding sun-diffuse is unchanged).
- **GLSL material hot-path optimization (fixes the FPS regression; identical output).** The first cut did ~42 `glGetProgramEnvParameterfvARB` + `glUniform4fv` calls **per diffuse_main draw**, resolved every uniform location via a per-draw `std::map<string,GLint>` lookup, AND did a toggle `glGet` on **every** draw in the game (even with GLSL off). Three safe changes, all preserving the captured values exactly: (1) **CPU toggle** — `PbrTune_GlslMaterialEnabled()` reads the slider value directly (no `glGet`); `GlslMaterial_Apply` early-returns on it, so toggle-OFF draws pay nothing and the all-draws `glGet` is gone. (2) **Cached uniform locations** — resolved once at link into a struct of `GLint` fields; no per-draw `glGetUniformLocation`/`std::map` string lookups. (3) **Per-frame vs per-draw split** — uniforms the engine sets from the camera (viewInv `env[89..92]`, camW) or the mod sets once per frame (tune sliders `env[24..30]`, pcf `env[32]`, shadow K `env[100..102]`) are uploaded **once per frame** via a swap-reset guard (`GlslMaterial_OnFrame()` in `OnSwapCommon`), since the program retains uniform state across the per-draw use/unuse cycle. Only the genuinely per-object/per-material params stay per-draw: the 3 engine vertex lights + ambient/scales (`env[73..95]`), the PBR material (`env[20..23]`), and fragment light0 (`env[86..87]`) — ~21/draw, down from 42, NOT cached because the engine varies them per object (caching would change shading). Net: per-draw `glGet`+upload halved, per-draw location lookups eliminated, toggle-off cost ~zero. Removed the now-unused `<map>`/`s_loc`. VS lighting init changed from a hardcoded `vec3(0)` to `vec3(uVI3.x)` to mirror the ARB `env[89].xxxw` exactly (still 0 for an affine viewInv, but no longer an assumption).

## 0.3.0-dev (tune overlay + sun system, shadow attempts cut)

- **In-game tune overlay** (`pbr_tune.cpp`): DEL key toggle, 19 sliders in 7 semantic groups (surface / material / reflection / local-light / sun-dir / sun-intens / sun-color). Pushes to `program.env[24..28]`. GDI→DIB→`glTexImage2D` font atlas (Aspyr's `wglUseFontBitmapsA` is silently no-op). `pbr_tune.ini` next to DLL for persist.
- **Backspace sun capture**: derives sun direction from current view matrix via `glGetFloatv(GL_MODELVIEW_MATRIX)` inside `glPushMatrix` hook at first non-identity rotation per frame. K2 doesn't use `glLoadMatrixf`, so the captured matrix is only available this way.
- **Parallel directional sun**: N·L term in fp shaders, gated by fl.x, color × intens × albedo. Replaces previous fake-sun-from-baked.
- **`DiagLog` stdio fallback** in `pbr_tune.h` writing to `logs/pbr_tune_diag.log`. Survives broken `file_logger` paths.
- **Env param re-push from `glClear` hook** — K2 stomps env state between FP binds; per-frame re-push needed.
- **Screen-space sun shadow — cut** after multiple iterations. Driver rejects `glCopyTexSubImage2D` for depth tex (`GL_INVALID_VALUE` after first frame). Full `glCopyTexImage2D` every frame works but is 4 FPS without throttle. Throttled snapshot caused temporal ghosting on dynamic geometry. Multi-tap linear-z `1/(1-z)` blew up at far depths. Cut entirely; depth-snapshot disabled. SS-shadow tune rows removed from overlay.
- **Depth-tex driver quirks documented**: Aspyr's `glCopyTexSubImage2D` rejects depth textures after first frame; offscreen `SwapBuffers` happen at small viewport sizes (inventory previews etc.) — must filter by viewport.
- **TMU 11+ rejection documented**: PBR siblings forced into TMU 8/9/10 with alpha-channel reuse.
